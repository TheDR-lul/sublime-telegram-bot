## Пидор-Рояль: Telegram UX и состояние UI

Этот документ описывает, как RPG-модуль живёт внутри Telegram: какие команды есть, как устроено одно «игровое сообщение», какие режимы (`mode`) и подпосостояния (`submode`) поддерживаются.

### 1. Общая идея: одно игровое сообщение

- Игровое взаимодействие строится вокруг **одного сообщения** (в ЛС или группе), которое бот:
  - создаёт при входе пользователя в RPG (`/rpg`);
  - затем постоянно обновляет через `editMessageText` + `editMessageReplyMarkup`.
- Состояние этого сообщения хранится в таблице `rpg_ui_state`:
  - `user_id` — `tguser.id`;
  - `chat_id` — чат, в котором живёт сообщение (ЛС или группа);
  - `message_id` — ID самого сообщения;
  - `mode TEXT` — текущий «экран» (`main`, `world_map`, `city_map`, `battle`, `inventory`, `profile`, `guild`, `building_*` и т.п.);
  - `submode TEXT` — уточнение внутри экрана (например, конкретное здание, подстраница инвентаря);
  - `payload_json JSONB` — любые дополнительные данные (координаты, выбранный город, список предметов, активный бой и т.п.);
  - `updated_at TIMESTAMPTZ`.

Важно: один пользователь может иметь несколько игровых сообщений (например, ЛС и группа), но для MVP достаточно одного основного в ЛС.

### 2. Команды и точки входа

#### 2.1. Личные сообщения с ботом

- `/rpg`:
  - если персонаж ещё не создан:
    - запускает мастер создания персонажа (см. ниже);
  - иначе:
    - открывает/создаёт главное игровое сообщение в ЛС и устанавливает `mode = main`.
- `/rpgme`:
  - быстрый просмотр профиля (можно редиректить на тот же UI `profile`).
- `/rpghelp`:
  - краткое описание того, что такое «Пидор-Рояль» и какие основные действия доступны.

#### 2.2. Групповые чаты

- `/rpg`:
  - шлёт короткое сообщение-тизер:
    - «Жми, чтобы открыть *Пидор-Рояль* в ЛС» с кнопкой `Открыть меню`.
  - по этой кнопке бот открывает ЛС/глубокую ссылку и создаёт/активирует UI там.
- `/pidorduel @user`:
  - инициирует PvP-дуэль.
  - В группе:
    - короткое сообщение о вызове;
    - боевой UI живёт либо в ЛС каждого игрока, либо в отдельном сообщении в группе (решается на этапе MVP).

Дополнительно: команды для гильдий/рейдов могут быть только кнопками в UI или дублироваться слэш-командами.

### 3. Режимы UI (`mode`) и переходы

#### 3.1. `main` — главное меню RPG

Текст:

- Заголовок «*Пидор-Рояль*».
- Краткое описание текущего состояния (уровень, где находится, есть ли активный бой/рейд).

Кнопки:

- `🧍 Профиль` → `mode = profile`
- `🗺 Выйти в мир` → `mode = world_map`
- `⚔ Дуэли` → `mode = duels`
- `👥 Гильдия` → `mode = guild`
- `🎒 Инвентарь` → `mode = inventory`
- `❌ Закрыть` → скрыть/удалить сообщение (по желанию).

#### 3.2. `profile` — профиль персонажа

Текст:

- Имя, уровень, класс/архетип.
- Основные статы (HP, Strength, Agility, Intellect, Vitality, Luck).
- Краткий пидорский flavor-текст («уровень пидорства», ачивки по верхам).

Кнопки:

- `⬅ Назад` → `mode = main`
- (в будущем) `🧬 Распределить статы`, `🎖 Ачивки` (можно слить с уже существующим `/achievements`).

#### 3.3. `world_map` — глобальная карта

Текст:

- Эмодзи-карта (окно вокруг игрока).
- Легенда (значение эмодзи).
- Описание текущей клетки (биом, уровень зоны).

Кнопки:

- Стрелки движения: `⬆`, `⬇`, `⬅`, `➡` (callback data с направлением).
- `🎯 Локация` — подробная инфа о текущей клетке/событии (открывает `submode = location_info`).
- `⬅ Назад` — возвращает в `mode = main`.

При входе на клетку города/деревни:

- `mode` меняется на `city_map`.

#### 3.4. `city_map` — карта города/деревни

Текст:

- Название города.
- Мини-карта города или список зданий.

Кнопки (пример для крупных городов):

- `🏪 Магазин` → `mode = building_shop`
- `⚒ Кузница` → `mode = building_forge`
- `🏰 Дом гильдий` → `mode = guild` с `submode = guild_home`
- `⚔ Арена` → `mode = building_arena`
- `🍺 Таверна` → `mode = building_tavern`
- `⬅ Выйти в мир` → `mode = world_map`

#### 3.5. `inventory` — инвентарь

Текст:

- Список предметов (постранично, с указанием редкости и краткого эффекта).

Кнопки:

- `◀ Стр. назад`, `▶ Стр. вперёд`
- `Экипировать` (при выборе конкретного предмета)
- `Использовать`
- `Выбросить/Продать` (позже)
- `⬅ Назад` → `mode = main`

#### 3.6. `battle` — боевой экран

Текст:

- «<Имя1> lvl X vs <Имя2/Моб> lvl Y»
- Полоски HP, эффекты (состояния).
- Лог последних ходов (3–5 записей).

Кнопки:

- `⚔ Атака`
- `✨ Скиллы`
- `🧪 Предметы`
- `🏳 Сдаться`

Подтипы:

- `submode = choose_skill` — показ списка скиллов с отдельными кнопками.
- `submode = choose_item` — показ списка предметов для использования.

#### 3.7. `guild` — гильдейное меню

Если пользователь не в гильдии:

- текст: тизер «организованного пидорства».
- кнопки:
  - `Создать гильдию`
  - `Найти гильдию`
  - `⬅ Назад`

Если состоит в гильдии:

- текст: название, уровень гильдии, количество участников, базовые бонусы.
- кнопки:
  - `👥 Состав`
  - `🧟‍♂ Гильдейский босс`
  - `⚙ Настройки` (только для лидера/офицеров)
  - `🚪 Выйти из гильдии`
  - `⬅ Назад`

### 4. Callback data и маршрутизация

Каждая inline-кнопка должна иметь компактный, но однозначный `callback_data`. Общая схема:

- Префикс для RPG-модуля: `rpg:...`
- Формат: `rpg:<mode>:<action>:<extra>`
  - Примеры:
    - `rpg:world:move:N`
    - `rpg:world:location_info`
    - `rpg:city:enter:shop`
    - `rpg:inv:page:2`
    - `rpg:battle:action:attack`
    - `rpg:battle:action:skill:fireball`
    - `rpg:guild:create`

На уровне диспетчера:

- Отдельный хендлер для callback-запросов RPG:
  - проверяет префикс `rpg:`;
  - парсит `mode/action/extra`;
  - загружает `rpg_ui_state` по `user_id` + `chat_id`;
  - дергает соответствующую функцию для обработки действия.

### 5. Мастер создания персонажа

При первом вызове `/rpg`:

1. Бот выводит форму:
   - спрашивает имя/никнейм персонажа (можно дефолтно взять из Telegram).
2. Выбор пола:
   - варианты: `Мужик`, `Очень мужик`, `Женщина (заблудилась?)`.
   - при выборе «Женщина»:
     - бот отвечает чем-то вроде:
       - «Извини, но это *Пидор-Рояль*, а не *Принцесса-Рояль*. Пол скорректирован до стандартного.»
3. Выбор архетипа/класса (опционально на MVP):
   - например: «толстый танк», «тонкий крит-пидор», «кастер».

После завершения мастера создаётся запись в `rpg_player`, и бот переводит пользователя в `mode = main`.

### 6. Приоритеты реализации по этому документу

1. **Таблица `rpg_ui_state`**:
   - минимальный набор полей: `user_id`, `chat_id`, `message_id`, `mode`, `submode`, `payload_json`, `updated_at`.
2. **Хендлер `/rpg`**:
   - создание персонажа, если его нет;
   - создание/поиск игрового сообщения и установка `mode = main`.
3. **Реализация маршрутизации callback-запросов RPG**:
   - разбор `callback_data` с префиксом `rpg:`;
   - загрузка и обновление `rpg_ui_state`.
4. **Экран `main` и переходы в `world_map`, `profile`, `inventory`, `guild`**:
   - минимальные тексты и кнопки.
