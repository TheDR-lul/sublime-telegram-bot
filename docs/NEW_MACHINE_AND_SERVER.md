# Новая машина разработчика и новый сервер

Краткий гайд: поднять окружение на **новом ПК** (Windows), настроить **SSH к прод-серверу**, перенести **базу** и задеплоить бота. Подробности пайплайна — в [DEPLOY.md](DEPLOY.md).

---

## Ключи и секреты

- **Публичный репозиторий:** приватные ключи и живые токены в Git не кладут.
- **Твой приватный репозиторий:** можешь хранить там то, что нужно для переноса с сервера (в т.ч. копию ключа один раз для `git clone` с нового хоста), если осознанно принимаешь риск утечки истории Git. Если ключ всё равно не будет использоваться дальше — это твоя схема.
- **`config.toml`** по умолчанию в `.gitignore`; чтобы закоммитить в приватный репо — `git add -f config.toml` (или вынести секреты в `.env` на сервере).

Я ничего не «стирал» на VPS: правки касались только файлов в локальном клоне при работе над документацией и деплой-скриптами.

## 1. Новый ПК (Windows): что установить

1. **Git** — клонирование репозитория.
2. **Docker Desktop** — если используешь `deploy.ps1` / `update-full.ps1` (сборка образа локально).
3. **OpenSSH Client** (обычно уже есть): `ssh`, `scp`.
4. **PowerShell** — скрипты `*.ps1` из корня репозитория.

Клонирование:

```powershell
# Приватный форк / основной репозиторий — подставь свой URL
git clone https://github.com/TheDR-lul/sublime.git
cd sublime
git checkout Sublime-Rust
```

Секреты:

```powershell
Copy-Item config.toml.example config.toml
# Отредактируй config.toml (токены и т.д.) — файл в .gitignore
```

## 2. Куда смотрит SSH у скриптов деплоя

Все скрипты `deploy.ps1`, `update.ps1`, `update-full.ps1`, `update-remote.ps1`, `setup-ssh-key.ps1` берут цель так:

1. Если задана переменная окружения **`SUBLIME_SSH_TARGET`** в формате `user@host` — используется она.
2. Иначе — значение по умолчанию из репозитория (сейчас `root@5.189.154.71`; после смены сервера лучше обновить дефолт в `scripts/DeploySshTarget.ps1` **или** всегда задавать `SUBLIME_SSH_TARGET`).

**Пример на сессию PowerShell:**

```powershell
$env:SUBLIME_SSH_TARGET = "root@YOUR.NEW.SERVER.IP"
.\update-full.ps1
```

**Постоянно для пользователя Windows:** «Переменные среды» → пользовательская переменная `SUBLIME_SSH_TARGET` = `root@...`.

Проверка входа:

```powershell
ssh $env:SUBLIME_SSH_TARGET "docker ps --filter name=sublime"
```

## 3. Первичная настройка SSH-ключа (без пароля при каждом деплое)

Один раз (подставь свой `SUBLIME_SSH_TARGET` или отредактируй дефолт в `scripts/DeploySshTarget.ps1`):

```powershell
$env:SUBLIME_SSH_TARGET = "root@YOUR.NEW.SERVER.IP"
.\deploy.bat ssh-key
```

Или вручную: `ssh-keygen -t ed25519`, затем скопировать содержимое `%USERPROFILE%\.ssh\id_ed25519.pub` в `~/.ssh/authorized_keys` на сервере.

## 4. Новый сервер (Linux): минимальная подготовка

1. Установи **Docker** и **Docker Compose plugin** (как в официальной инструкции для твоего дистрибутива).
2. Создай каталог деплоя (по конвенции скриптов): `/root/sublime-deploy`.
3. На первом деплое скрипты сами докинут туда файлы; тебе нужно один раз создать **`/root/sublime-deploy/.env`** на сервере:

   ```bash
   TELEGRAM_BOT_TOKEN=твой_токен_основного_бота
   ```

4. Открой в фаерволе исходящий интернет (для Telegram и образов Docker при необходимости).

Дальше с локальной машины — первый деплой: см. [DEPLOY.md](DEPLOY.md), раздел *First-time deploy* (`.\deploy.ps1`).

---

## 5. Перенос базы данных со старого сервера

1. Сними дамп на старой машине (на сервере уже есть скрипт):

   ```bash
   cd /root/sublime-deploy && ./remote-backup-db.sh
   ```

   Либо с локального ПК пайплайн `.\update-full.ps1` сам делает backup и кладёт копию в локальную папку `backups/`.

2. Скопируй `.sql` на новый сервер (scp / любой канал).

3. Подними **`db`** через `docker-compose.deploy.yml`, затем залей дамп **до** или **после** первого `migrate` — осторожно: если нужна именно восстановленная база поверх пустой, логика такая:
   - вариант A: поднять только Postgres, восстановить дамп в БД `sublime_bot`, потом `compose up` бота и миграции (если схема совпадает с миграциями в образе — см. [DEPLOY.md](DEPLOY.md) про `VersionMismatch`);
   - вариант B: следовать готовой команде из [DEPLOY.md](DEPLOY.md) в разделе *Backup location* (через `psql` в контейнер `db`).

Если версии миграций на образе новее дампа — обычно достаточно после restore прогнать `sublime migrate` из контейнера бота.

---

## 6. Чеклист после переезда

- [ ] `SUBLIME_SSH_TARGET` или дефолт в `scripts/DeploySshTarget.ps1` указывает на **новый** IP/хост.
- [ ] `config.toml` на ПК и `.env` на сервере заполнены, не в Git.
- [ ] `ssh ... docker ps` показывает `sublime-bot` (и при необходимости `sublime-watchdog`).
- [ ] В Telegram бот отвечает; при использовании watchdog — проверка алертов.
- [ ] Со **старого** сервера: остановлены контейнеры, удалён старый SSH-ключ из списка доверенных на других машинах при необходимости.
